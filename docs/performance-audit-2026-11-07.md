## Загрузка и кеширование

Начальный экран загружает код интерфейса. Для открытия меню и статистики не нужны
модели, карты арен или все боевые портреты. WebGL-превью архива создаётся при первом
открытии Characters; тогда готовятся ресурсы выбранного персонажа. Ландшафт Nagrand
тоже больше не создаётся при открытии меню.

Перед матчем готовятся выбранная арена, участвующие персонажи, их дополнительные
формы, оружие, анимации и портреты. Каждая машина показывает свой прогресс. Сервер
блокирует команды до подтверждения готовности всех участников; устаревшее
подтверждение не может открыть следующий матч серии. Отсчёт длительности матча
начинается после загрузки. Переподключение получает текущее состояние ожидания.

Загрузочная шторка остаётся до завершения установки моделей, подготовки шейдеров
и первого скрытого рендера видимой сцены. Ошибка обязательного ресурса оставляет
экран с повторной попыткой вместо открытия матча с процедурной заглушкой.

GLB-кеш хранит разобранный шаблон в пределах страницы. Адреса файлов содержат хеш
содержимого; production-сервер отдаёт `/assets` с `max-age=31536000, immutable`.
HTML остаётся с перепроверкой актуальности. Сборка не дублирует игровые ресурсы
под исходными URL и не включает старые неиспользуемые GLB.

HTTP-кеш сохраняет скачанные байты, но не готовые объекты Three.js. После обновления
страницы выбранные GLB всё равно нужно разобрать и создать GPU-ресурсы. Браузер может
вытеснять файлы из кеша. Поэтому полоса показывает подготовку ресурсов, а не обещает
повторное скачивание указанного числа МиБ.

## Графика и кадр

- Периметр Lordaeron: **1 582 878 → 791 418 треугольников**. Упрощён только статический
  периметр: ratio 0,5, error 0,001. Топология персонажей, веса и анимации не упрощались.
- Текстуры моделей размером 4096 уменьшены до 2048. Цветные текстуры переведены
  в WebP quality 90; карты данных не подвергались этому цветному сжатию.
- Боевые портреты: WebP quality 88, максимальная сторона 1024, сохранена прозрачность.
  Для профилей не увеличивалось исходное разрешение. Текстуры земли Nagrand:
  WebP quality 92, максимальная сторона 2048.
- Дополнительное Meshopt-сжатие буферов уменьшает размер файла. Само по себе оно
  не уменьшает число рисуемых треугольников; для этого отдельно упрощён периметр.
  [Описание Meshopt compression](https://gltf-transform.dev/modules/extensions/classes/EXTMeshoptCompression).
- Основной цикл не обновляет и не рисует скрытую арену в меню/архиве и скрытой вкладке.
  Доступность целей пересчитывается при изменениях состояния/выбора, а не каждый кадр;
  пульсация остаётся покадровой. Убраны проверки достижимости атаки без режима атаки и
  ненужные raycast/layout-операции выключенного превью движения.
- WebGL-контексты превью лобби освобождаются при входе в матч и выходе из комнаты.

Оценка всех встроенных текстур моделей как RGBA + mip-уровни уменьшилась примерно
**1061 → 549 МиБ**. Это не замер VRAM: оценка не учитывает дедупликацию, фактические
форматы GPU, framebuffer, shadow maps и накладные расходы браузера. Весь набор
не загружается одновременно. Три пары портретов визуально сравнены при размере
карточки; внешний вид упрощённого периметра в игре должен проверить пользователь.

## Сервер и оставшиеся ограничения

`npm run audit:performance` выполняет по 200 прогонов Guard на подготовленных
duel/FFA-состояниях и состоянии с синтетическим журналом на 2000 записей.
В отдельном завершающем запуске p95 обработки команды составил 0,076–0,085 мс
для коротких состояний и 0,288 мс для длинного журнала. p95 JSON-сериализации:
0,028–0,030 и 0,279 мс соответственно. Эти данные не охватывают сложные бои,
сетевую задержку, конкурирующие комнаты и производственное оборудование.

Полное состояние по-прежнему пересылается после команды. В синтетическом примере
2000 строк увеличили его примерно с 6,65 до 118,71 КиБ. `applyCommand` клонирует
состояние, а диагностическая запись дополнительно проецирует/сравнивает его.
При долгих матчах это остаётся кандидатом для профилирования. Синхронная запись
завершённого матча в outbox также может задержать event loop на медленном диске.

Lordaeron и после уменьшения остаётся тяжёлой геометрией. Разные эффекты могут
изменять число видимых источников света и создавать новые варианты шейдеров;
прогрев начальной сцены не гарантирует отсутствие первого shader hitch у всех
заклинаний. Архив сохраняет ранее открытые модели в памяти страницы. Крупные JS-чанки
остаются предупреждением сборщика; ExcelJS намеренно загружается только для импорта.
Эти вопросы требуют отдельного замера кадров/матч-дампа, прежде чем менять визуалы
или сетевой протокол дальше.

## Проверки и воспроизводимость

Прошли typecheck, production build, `check:assets`, WebSocket-проверки debug-server
и perk-mode-server (duel, FFA, оба варианта серии), debug-client/recording/reader,
проверки Archmage, Obi-Wan, Merylin, John Christ/Spirit, предметов Orkk и координат мечей.
В `check:assets` проверяются состав ресурсов, дополнительные формы, ожидание двух
клиентов, устаревшие подтверждения, хеши, содержимое сборки и HTTP 200/304/Cache-Control.

Общий `check:rules` падает на строке 1313 при выборе Combat Card в clamped-defense
сценарии. То же падение воспроизведено на изолированной копии чистого `HEAD`
в `output/performance-baseline`; к оптимизации ресурсов оно не относится.

Оптимизация воспроизводится скриптом `scripts/optimize-runtime-assets.mjs`;
команда установки его отдельных инструментов указана в начале файла.
При записи и повторном чтении изменённых GLB проверены имена/значения всех
анимационных каналов, время, интерполяция, привязки и inverse bind matrices.
Для статического упрощённого периметра это исключение не требуется: скелета и клипов нет.

Исходники и точные результаты сохранены локально в
`output/performance-assets-originals/optimization-results.json`; исходные файлы
лежат рядом с сохранением структуры путей. Сравнение портретов:
`output/performance-assets-originals/artwork-comparison.png`.
