# Da Orkk on Nagrand

Select **Hotseat → 1 versus 1 → Nagrand → your Character → Da Orkk · Tactical Bot**. You control Player 1; Da Orkk controls Player 2. This always starts Standard mode. Merylin Bot and manual Hotseat opponents remain available. Other arenas, Free For All, Perk Mode and Best-of-Three are outside this bot's scope.

The bot manages Rage as Attack ammunition, pressures melee range, considers High Ground and Quest objectives, and weighs survival against Card preservation. It forecasts Shield throw collisions, recall routes and crossed enemies, HP/Rage creation payments, Kyk directions and momentum, healing and status removal. It handles opening Focus, Phase progression, Spell Echo, defense, Combat Cards and required discards through the same commands and rules as a human.

`src/orkk-bot.ts` supplies Da Orkk's Card priorities, resource values and targeting choices. `src/nagrand-bot-core.ts` supplies shared engine validation, hypothetical combat evaluation and bounded search. Targeting sequences are forecast through their results before committing to a Perk. A Kyk target with no selectable on-board direction is excluded; the bot avoids starting an uncompletable targeting sequence. Each real command is followed by a new observation. There is one deterministic heuristic difficulty, with no claim of optimal play.

Both bots use the existing filtered observation boundary in `src/merylin-bot-observation.ts` and Worker in `src/merylin-bot-worker.ts`. These filenames remain for compatibility; the controller and Worker select the appropriate character policy through `src/nagrand-bot.ts`. The Worker never receives the human's hidden Hand, shuffled draw order, unrevealed Attack, private extra Combat Card submission, histories or deferred results. The bot's own shuffled Deck order is also masked. Combat guesses use the opponent's authored character Card pool rather than actual hidden Cards. See [Merylin's information boundary](merylin-bot.md#information-boundary).

Verification commands: `check:orkk-bot`, `check:orkk-bot-match`, `check:orkk-bot-ui`, `check:orkk-bot-worker`. Build before the Worker check. The match check uses 27 seeded games against simple scripted opponents spanning all nine Hotseat characters. These checks measure legality/completion rather than strength against humans. Targeted tests cover Rage attacks, Shield lethality and recalls, safe creation payments, Kyk edge collisions and corner exclusions, healing, all Level 3 Perks, Focus/Phase choices, hidden-information invariance and isolated RNG. Controller checks cover Player 1 perspective/input, filtered messages, stale responses and retry; the production Worker runs under a Node message shim. No browser automation is used.
