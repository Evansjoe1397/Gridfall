# Короткие фризы: HUD и шейдеры — 8 ноября 2026

В коде найдены два механизма, способных создавать неравномерные кадры при высоком
среднем FPS. Их наличие подтверждено проверками вне браузера; стоимость на машине
игрока пока не измерена.

## HUD

Кадровые функции меняли классы и `left/top`, а затем в тех же циклах читали
`getBoundingClientRect`, `offsetWidth` и размеры canvas. Несколько одновременно
живущих подписей могли повторять этот цикл несколько раз за кадр. Кроме того,
`updateDamageVisuals` запрашивал прямоугольник слоя даже без всплывающих чисел.

Теперь размеры рядов статусов и чисел поступают через `ResizeObserver` и кешируются.
Экранные границы ряда рассчитываются из проекции персонажа, масштаба и измеренного
размера — без запроса геометрии браузера. Координаты относятся к текущему кадру,
поэтому кеш не добавляет задержку положения на один кадр. Анимационные подписи
перемещаются через `translate3d`, а не через меняющие layout `left/top`.

В шести проверяемых функциях HUD больше нет синхронных чтений геометрии. Это
не означает отсутствия layout во всей игре: создание интерфейса, смена его
содержимого и изменение окна по-прежнему требуют нормального layout браузера.

## Источники света

В установленной версии Three.js `numPointLights` входит в `getProgramCacheKey`.
Появление света у заклинания может менять ключи программ у материалов сцены,
включая уже показанные объекты арены. Проверка использует реальную реализацию
`WebGLPrograms` и подтверждает разные ключи при изменении числа ламп.

Перед открытием арены прогреваются текущий набор света и варианты с одной,
двумя и тремя дополнительными PointLight. Это временные лампы нулевой интенсивности:
они удаляются после прогрева, включая путь ошибки. Постоянное число ламп и
освещение матча не увеличиваются. Кадровый цикл арены на время прогрева приостановлен;
одновременные запросы подготовки объединяются.

Прогрев переносит часть работы под загрузочную шторку, но не охватывает все
возможные материалы, количества света, тени и сочетания эффектов. Он также может
удлинить подготовку сцены; её длительность и число добавленных программ записываются
событием `render.shader-warmup`.

## Замеры в реальном матче

В Ctrl+D добавлены:

- `HUD CPU p95 / max`: время JS-участка обновления HUD.
- `Render CPU p95 / max`: время вызова `renderer.render`, включая возможное
  ожидание драйвера. Это **не измерение асинхронной работы GPU**.
- `Shader programs / growth frames`: размер кеша программ и число кадров,
  в которых он вырос во время отправки рендера.
- `Long frames / forced layout max`: длительные кадры и максимум принудительного
  style/layout, если браузер предоставляет соответствующий API.

CPU-выборка ограничена 600 кадрами. Наибольшие CPU-значения сохраняются отдельно,
чтобы короткий пик не потерялся между диагностическими снимками. Метрики попадают
в `diagnostic.sample → renderer.frameWork`; рост кеша — в `render.program-growth`.

Опциональный Long Animation Frames observer записывает `render.long-frame`:
длительность, `forcedStyleAndLayoutMs` и имя функции с наибольшим атрибутированным
вкладом. События ограничены одним в секунду, а счётчики учитывают все полученные
записи. API сообщает кадры длиннее 50 мс и даёт частичную атрибуцию скриптов;
нулевое значение не доказывает отсутствия меньших задержек или всего layout.
[Документация Long Animation Frames](https://developer.chrome.com/docs/web-platform/long-animation-frames).

После обновления страницы воспроизведение стоит выполнять с закрытой панелью
диагностики, чтобы её обновления не добавляли работу интерфейсу. После заметного
фриза Ctrl+Shift+D сохраняет дамп. По совпадению роста кеша, времени отправки
рендера, forced layout и событий заклинаний можно будет сузить причину.

## Проверки

`npm run check:frame-stalls` проверяет кеш размеров без геометрических getters,
совпадение расчётных границ с CSS-матрицей, отсутствие layout-чтений в кадровых
функциях HUD, ключи Three.js, прогрев и очистку ламп при успехе/ошибке/конкурентных
запросах, ограничение памяти профайлера и подключение опционального observer.

Также проверяются typecheck, production build, камера, animation-stalls и
`check:debug-client`, `check:debug-recording`, `check:debug-reader`, `check:debug-server`.
Браузерная проверка и замеры FPS/GPU не выполнялись согласно AGENTS.md.
